A **domain** is the logic behind a personalised feature of the GOV.UK app. It sits between the app
and the upstreams that hold the data it needs.

Each domain is an Amazon API Gateway at its own domain name, under its domain account's hosted
zone. A Lambda proxy integration hands every request to the domain's code. The
[Frontdoor](/flex-platform/frontdoor/overview/) routes requests to the domain. The app never calls
a domain directly. See [Hosting a domain](/flex-platform/domains/hosting/).

Developers outside the platform team write domains. A domain defines the behaviour the app needs:
it can expose data from one upstream, combine several upstream calls, or compute a response without
an upstream call. See [Designing a domain](/flex-platform/domains/designing-a-domain/) for examples
and the boundary between domain logic and gateway code.

## Where a domain's code lives

Domain code lives with the team that writes it, in its own repository, and declares its routes with
the [domain SDK](#domain-sdk). This repository does not include a domain skeleton. Where a domain
runs is in [Hosting a domain](/flex-platform/domains/hosting/).

## Releasing a domain

A domain's pipeline uploads its code to the platform and releases it to its development
environment, which runs inside the platform's production stage. From there, the domain will
promote the version to staging, and then to production: promotion is planned. See
[releasing a domain's function](/flex-platform/domains/hosting/#releasing-a-domains-function).

## Network

A domain's Lambda runs in `isolated` subnets, with no route to the internet. It reaches upstreams
through a gateway. An upstream might be another team's API, an AWS-hosted service or a third
party.

## Calling gateways

A domain calls a gateway through the gateway client, `@govuk-once/flex-gateway-client`. It
invokes the gateway's Lambda function directly through the Lambda API, not over HTTP. Codegen
builds each gateway a [client package](/flex-platform/codegen/overview/#the-client-package) holding
the gateway's [call contract](/flex-platform/codegen/call-contract/) and one function, named for
the gateway, that creates a client typed by it. A domain installs the gateway client, the package
of each gateway it calls, and `@aws-sdk/client-lambda`, the gateway client's one peer dependency.

```ts
import { GatewayInvocationError } from "@govuk-once/flex-gateway-client";
import { createUdpClient } from "@govuk-once/flex-gateway-udp-client";

const udp = createUdpClient();

const response = await udp.getIdentity({ serviceName, identifier });
```

The client takes no settings, so a domain is never given a function name or an ARN. It invokes the
function `gateway-<environment>-<id>`, through its one alias, `live`, in the domain's own account
and region. It takes the environment from the `FLEX_ENVIRONMENT` variable, which a
[release](/flex-platform/domains/hosting/#releasing-a-domains-function) sets on every domain's
function. It reads the variable on its first call, not as it is created, so a module can create
its client as it is imported, and a call without the variable fails. The name follows the
[template every resource name follows](/flex-platform/infrastructure/overview/#rules-for-stacks-and-constructs),
so a domain's permissions can name its own environment's gateways and no other's. The Lambda
client takes the region and credentials from the function it runs in. Gateways and domains share
an account, and each gateway's stack deploys its function under this name. In a test that
calls a gateway, set `FLEX_ENVIRONMENT`, and the SDK's own `AWS_ENDPOINT_URL_LAMBDA` variable
points the client at a stand-in for Lambda's API.

The client has a function for each of the gateway's operations, named for it and taking its input,
and nothing else. An editor shows each with the description the configuration gives its
operation. A call sends one [envelope](/flex-platform/gateways/overview/#a-request) and returns the
gateway's response, typed by the operation: an error envelope or one of its outcomes.

The client sends each call only once, with the SDK's retries turned off (`maxAttempts: 1`): a
retried invoke could repeat an upstream write, and deciding whether to retry needs to know the
operation and the deadline. It leaves the invoke's `LogType` unset, so it never asks for the end of
the gateway's execution log.

A call's second argument, its options, can carry a `signal` that stops the client waiting.

### The caller context

What a call sends on its caller's behalf comes from the caller context, not from the call. It is
set once for the whole of a domain's invocation, by running the handler inside `withCallerContext`
from `@govuk-once/flex-gateway-client/caller`. Every call made from the handler, however many
`await`s deep, then carries it. The [domain SDK](#domain-sdk) does this for every handler it
calls, so a domain developer does not. The entry is kept apart from the client's main one so that
an editor does not offer it, and nothing exports a way to read the context back.

```ts
import { withCallerContext } from "@govuk-once/flex-gateway-client/caller";

withCallerContext({ deadline, secure }, () => handler(event));
```

- `deadline` is when the caller stops waiting, in epoch milliseconds. The client abandons a call
  still waiting then, and does not send one made after it. The caller keeps its own margin for
  answering after a call. The deadline is not yet sent to the gateway, which works out its own
  from its invocation.
- `secure` is `{ token }`: the [caller token](/flex-platform/frontdoor/caller-token/) from the
  request's `x-flex-secure` header, passed on unchanged. The gateway verifies it, and compares an
  operation's [bound fields](/flex-platform/gateways/configuration/#secure-bindings) with its
  claims. Without it the client sends none, and the gateway refuses every call with
  `UNAUTHENTICATED`, even for an operation with no bindings.

A call made outside a caller context is refused before anything is sent: the client throws an
`Error`, not a `GatewayInvocationError`, because the mistake is in the caller's code.

### When the gateway does not answer

The client throws a `GatewayInvocationError` instead of returning a response. Its `reason` is one
of:

| Reason | When |
|---|---|
| `invoke_failed` | Lambda did not take the call: it was throttled, not permitted, or named no function, or Lambda was unreachable. |
| `function_error` | The function failed instead of answering, as it does when it times out or fails to start. |
| `invalid_response` | The answer is not a response envelope. |
| `aborted` | The call's `signal` stopped the wait. The call may still have completed, and it is not sent again. |
| `timed_out` | The caller's deadline passed, before the gateway answered or before the call was sent. One that was sent may still have completed, and it is not sent again. |

The message is fixed text, with the SDK error's name for `invoke_failed` and Lambda's
`FunctionError` value for `function_error`, so it is safe to log. It never includes the service's
message or the function's error payload, which can hold request data.

### What the client checks

The client checks the response envelope's shape. It reads only the fields an envelope has, and
only those the answer holds itself, never inherited ones. It refuses an error code the platform
does not define. It leaves out a `meta` value that is not a scalar, because every part of `meta`
is optional to a caller.

The client does not check the outcome's data, or that the outcome is one the operation declares.
That is the gateway's job, done against its schemas before it answers. A gateway's contract only
changes [compatibly](/flex-platform/gateways/compatibility/), so a domain compiled against an
earlier version still understands every answer. What an upstream changes without warning, the
gateway refuses as `UPSTREAM_CONTRACT_VIOLATION`.

## Domain SDK

The domain SDK, `@govuk-once/flex-domain-sdk` in `domains/sdk`, is the package a domain's code uses
to declare its routes, type its handlers and answer its requests:

- [Domain configuration](/flex-platform/domains/configuration/) is what a domain declares, and
  the rules each field is held to.
- [Requests](/flex-platform/domains/requests/) is how the SDK answers a request.

Serving requests from a domain's function with it is planned, and it is not published yet. It
takes `zod` and `@govuk-once/flex-gateway-client` as peer dependencies, so a domain's schemas, its
gateway calls and the SDK share the domain's own copy of each, and one caller context.

## API specifications

The SDK builds a domain's OpenAPI 3.1 document from its
[configuration](/flex-platform/domains/configuration/) alone, without running a handler. The SDK
exports nothing a domain can build it with yet.

The document describes the domain's routes and schemas, and the answers the SDK sends itself:

- **Each route as an operation.** Its `operationId` and `description` when it sets them, its path
  and query parameters, its body, and each response it declares. A parameter is required unless its
  field is optional or has a default.
- **What the SDK answers on every operation.** Its
  [own answers](/flex-platform/domains/requests/#the-sdks-own-answers) on a route, 400, 500, 502
  and 504, plus 415 on a route with a body, and 503, the one server error only a handler answers
  with. Each has the platform's failure body, `PlatformError`. Where a route declares a 400 too, the
  body is `anyOf` the two: `oneOf` would refuse a route's body that also matches `PlatformError`.
  The 404 and 405 for a path or method no route has belong to no operation, so are not described.

Publishing a domain's document is planned, through an endpoint for a domain's metadata uploads,
with an endpoint in the Frontdoor to read the published documents. When a document is published,
the platform adds what it applies to every domain: the server, the access token, and the
Frontdoor's and API Gateway's answers. The SDK's document leaves them out, so that the platform
writes what it owns rather than accepting it from a domain.

Each schema is described as Zod writes it in JSON Schema: a parameter or body as the request is
validated, a response as it is sent. So a field with a default is optional in a body and always
there in a response. A schema named with `.meta({ id })` is a component every use refers to, or
two, `<id>` and `<id>Input`, when its input and output differ or a named schema it holds is two.
A recursive schema must be named, so a client has a name for its type.

Building the document checks the configuration first, then throws a `DomainConfigError` listing
every schema it can't describe, each as `<field>: <problem>, <fix>`:

- a schema holding what JSON doesn't carry, such as `z.date()`, or a response with a transform;
- a recursive schema with no name;
- an id used for two different schemas, or holding a character other than letters, digits, `.`,
  `_` and `-`;
- a component name already taken, such as `PlatformError`, or an id `TodoInput` beside a `Todo`
  that is two.
